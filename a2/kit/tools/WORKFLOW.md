# Poly A2 — несколько ИИ в одном рабочем процессе

Это инструкция рабочему ИИ. Человек называет своё дело; помогите выбрать разрешённые копии исходников, роли и пределы. Не требуйте от новичка вводить команды самостоятельно.

`workflow.py` возвращает ответы исполнителя и независимого проверяющего ведущему ИИ. Можно разрешить одну доработку. Пример: подготовить сравнение предложений по двум исходным текстам, затем проверить каждую цену и ограничение по оригиналу. Подходит и для проверки расчёта из CSV, плана по заметкам или учебного объяснения. Роли здесь исполняют разные программы Codex и Claude Code; доступность обеих подписок проверяется адаптером на этом компьютере.

До запуска покажите человеку, какие тексты уйдут двум ИИ. Используйте только согласованные UTF-8 копии, до 18 КБ суммарно; уберите секреты и ненужные личные данные. Уточните задачу и критерий полезного результата. Вход в существующие подписки обязателен; отдельно оплачиваемый API не используется. Ограничение вызовов и времени не гарантирует цену или оставшуюся квоту подписки. Внешний запуск требует согласия человека.

После согласия рабочий ИИ может выполнить из корня комплекта:

```sh
python3 tools/workflow.py --task-file task.txt --source approved.csv --output new-run --producer codex --reviewer claude-code --max-calls 2 --max-seconds 300 --stop-file STOP-POLY-A2 --allow-network
```

Новая папка `new-run` не должна существовать. Два вызова — исполнитель и проверяющий; `--max-calls 3` добавляет ровно одну доработку. Каждый вызов ограничен адаптером 90 секундами. Файл `STOP-POLY-A2` останавливает процесс перед следующим вызовом; текущий вызов завершается или достигает своего таймаута. При ошибке, исчерпании времени, смене исходника или слишком длинном следующем поручении автоматического повтора нет. Уже полученные ответы остаются в папке. Для повторения на другом входе выберите новые согласованные копии и новую папку.

В `REPORT.html` человек видит ответы, причину остановки и согласованные исходные тексты. Те же точные входные копии сохранены приватно в `ORIGINALS.json`; если исходник позже изменён, нужна новая сверка. `REPORT.json` хранит роли, число попыток и хэши. Исполнитель нумерует действия и существенные утверждения; критик отдельно указывает для каждого исходную строку, самостоятельный расчёт и вывод «подтверждено / опровергнуто / не проверено». Пропущенное действие также отмечается. Предложенное внешнее изменение остаётся непроверенным до наблюдения настоящего эффекта.

Никакой ответ ИИ не исполняется как код. Ведущий обязан сверить каждое действие, числа, цитаты и выводы с настоящими оригиналами, показать исправления и неопределённость. Вердикт критика тоже является ответом ИИ. Хэш проверяет неизменность байтов, а не правильность содержания. Не отмечайте пользу по одному отчёту или совпадению мнений. Отдельно проверьте результат на втором настоящем входе; это ещё не проверено на компьютере человека.

## Check the agreed task too

`TASK.txt` is the exact agreed task, saved privately beside the answers. `REPORT.json` records its SHA-256 and `REPORT.html` shows the task and acceptance conditions before the answers. Compare each condition with the original evidence; saving the task or receiving a reviewer answer does not certify success. Older runs without this file retain their original evidence and are not silently rewritten.
