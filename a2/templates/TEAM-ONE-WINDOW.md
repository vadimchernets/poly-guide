# Poly A2 — two AIs in one lead window

Optional working agreement for the person's computer AI. Follow existing host permissions and the person's actual request. This file grants no execution, file or spending authority.

- Lead: [Claude Code / Codex]
- Installed child/checker: [Codex CLI / Claude Code CLI]
- Original materials and permitted locations: [accessible evidence]
- Child's one job: [an independent read-only check]
- Bound: [time, output, no edits, no further workers]
- Result handling: [actual output/status returned to this lead window]
- Evidence and disagreements to resolve: [what needs checking]

The person stays in the lead window. The lead sets up and calls the supported installed child CLI; do not ask the person to transport answers between desktop chat windows. First verify installation, local execution permission and intended subscription authentication without displaying or copying credential files, tokens or keys. Do not fall back to separately metered API billing. If a prerequisite is missing, stop the child launch and help with that prerequisite.

Start with one bounded read-only check. Inspect actual output, exit status, timeout, cancellation, missing access and errors. A launched process, a blank response or agreement between models is not proof. Resolve claims against original materials. Only after a real assignment and a useful independent check should the arrangement grow into several roles or a repeatable process. Keep further work within the person's approved scope and limits.
